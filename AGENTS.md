# Workflow-kit maintenance

- Edit root `skills/`, `scripts/`, and `templates/`. `plugins/workflow-kit/` is
  generated by `node scripts/build-codex-package.mjs`; never hand-edit it.
- `skills/*/bundled/` is generated by `scripts/build-skill-bundles.mjs`, also run
  by the Codex package build. Edit canonical owners, never bundled copies.
- Model routing is owned by `scripts/lib/model-policy.mjs` and
  `templates/model-routing.md` (a reference, not a catalog skill). Launch
  mechanics are owned by `templates/t3-delegation.md` (T3 Code orchestrator) and
  `templates/cli-delegation.md` (Codex/Claude CLI fallback); no companion policy
  copies are needed.
- Effort above medium needs a recorded reason unless it is an owner-selected
  default. Never use ultra. xhigh is allowed only on GPT-6.1 Sol; max only on Luna.
  Preserve explicit allowed user choices. Owner-selected defaults: Luna high
  (xhigh/max freely, never below high); Sol high for Codex coding, review and
  orchestration, Sol xhigh for design and intense reasoning; Opus 5.5 high for
  Claude coding, design, review and orchestration (Fable high design alternative;
  Fable low/medium review alternative, then fresh Codex if neither is available);
  Fable 5.1 high for Claude intense reasoning. Astra is an explicit pin only.
  Opus 5.5 never runs at low. Opus 5 is retired. Record routing evidence.
- Preserve local repository tracker/status mappings and independent review,
  final-SHA verification, and human acceptance boundaries.
- Preserve unrelated worktree changes. Do not change global plugin/model settings
  when implementing package changes. Test installation in an isolated home.
- Validate with `node scripts/build-codex-package.mjs --check`,
  `node scripts/validate-package.mjs`, and `node --test test/*.test.mjs`.
  Optional native install check: `python scripts/test-codex-install.py`.
- Keep Claude manifest, Codex manifest template, lifecycle marker, and helper
  version synchronized. Commit/push only when authorized by the user.

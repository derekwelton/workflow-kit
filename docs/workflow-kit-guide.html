02 / WHAT YOU ARE BUYING WITH THE COMPLEXITYThe value is continuity and review discipline

Workflow-kit gives an AI agent a repeatable way to carry work from a request to an independently reviewed result, while keeping the tracker and handoffs useful. Its strongest value is continuity and review discipline. Its largest usability problem is that everyday actions, specialist workflows, and background instructions all appear in one skill catalog.

Continuity

The next session knows where you left off

Issues, decisions, verification evidence, and handoffs provide a durable record. That matters when work crosses sessions, machines, or people.

Quality gates

“Implemented” is not confused with “accepted”

Independent review, verification of the actual final code, and human review prevent a confident author from declaring their own work finished.

Consistency

The agent follows the repository's rules

Tracker mappings, model effort, issue updates, and code design guidance can operate in the background. You should not need to repeat them with every request.

Scale, when necessary

Several changes can arrive as one testable batch

Orchestration coordinates isolated workers, separate reviews, and combined verification. That overhead pays off on a real workload.

Skill, command, tool: what is the difference?

Skill: instructions the agent follows. Command: a way to invoke those instructions. Helper: executable code supporting them. Template: a reusable report or repository convention.

The kit does not supply a new model, browser, search engine, or tracker service. It coordinates capabilities available through your host and connected tools. Native and generated copies expose the same catalog, not extra workflows.

Claude uses /workflow-kit:<directory>. Codex uses $<skill-name> or its surfaced namespace. The naming exception is Claude /workflow-kit:orchestrate versus Codex $orchestrate-queue.

Match the process to the work

A small, understood bug

Reuse or start an issue → implement the fix → relevant verification → independent code-review → human acceptance and authorized closeout.

Skip the interview, prototype, formal spec decomposition, and batch orchestrator unless a real uncertainty appears.

A large, uncertain feature

Start an issue → resolve the specific unknown with research, an invited interview, or a prototype → capture decisions with to-spec → split only if needed → implement → independent review.

Planning techniques are choices, not a required sequence. Use wayfinder only when the investigation itself spans substantial work.

Several issues that must work together

Select a bounded workload → orchestrate isolated work and independent issue reviews → verify the combined integration branch → human tests and accepts → integrate-reviewed.

This is where manifests, review receipts, worktrees, and integration gates earn their overhead. Do not scale this machinery down to every tiny fix.

04 / MY ASSESSMENTSimplify the surface before deleting the machinery

Keep five everyday actions visible: new-feature, implement, code-review, board, and handoff. Put specialist workflows behind an advanced section, and treat policies as background guidance. This is an editorial recommendation, not a measured usage ranking or a change to the installed commands.

The clearest excess is in the interface. Planning is spread across many names, several audits sit beside daily actions, and background policies look like commands you forgot to learn. That is a strong case for better grouping. It is not yet evidence that every underlying capability should be removed.

Packaging, installation, and the separate codex-kit companion

.claude-plugin/plugin.json declares the Claude package. .agents/plugins/marketplace.json advertises the native Codex package. plugins/workflow-kit/ is generated from the root sources. These copies do not multiply the 30 skills.

codex-kit is a separate project. Its review/job execution and control commands are not additional workflow-kit skills. workflow-kit owns lifecycle, review, and integration rules; the companion supplies execution capabilities when configured.

Refresh has two locations: update the installed plugin on each machine, then use workflow-update in each adopted repository. An already-loaded session can need a restart or reread. The source version shown here does not prove what your current host has loaded.
